# Appendix A — Data dictionary

Column-by-column reference for the 12 tables. The model overview is in Part A.


### dim_site — one physical plant (Type 1)

| Column | Description |
|---|---|
| `site_key` | Our own ID, e.g. `S-001`. Generated by us. Agencies never see it. |
| `site_name` | Display name we chose, e.g. "Acme Pharma Unit II, Sangareddy". |
| `country_code` | ISO-2. |
| `city` | Normalised city. |
| `address` | Normalised address. Used for matching and facets. |
| `is_active` | `true` normally; `false` once merged into another site. The target is visible in the bridge: the site's identifiers now point at the survivor, grouped by one `decision_group_id`. |
| `created_at` | When we created the site. |

Type 1 because site *names* changing is not the history customers care about; the history
that matters (which facts belonged to the site on date X) lives in the bridge.

### dim_site_identifier — the bridge (SCD2)

One row = "identifier X belongs to site Y from date A to date B". A phone book from agency ID
to our site.

| Column | Description |
|---|---|
| `identifier_type` | `FEI` (FDA), `EU_SITE_REF` (EU), `LETTER_ID` (warning letter with no FEI, matched on its own), `WATCH_ID` (a customer's watchlist row). |
| `identifier_value` | The ID: `3004521877`, `LOC-118842`, `WL-320-26-118`, `9912`. |
| `site_key` | Which of our sites it points to. |
| `match_method` | `EXACT_ID` (shared agency ID), `RULE` (deterministic rule), `FUZZY` (name/address score), `STEWARD` (human decision). |
| `match_score` | 0–1 for FUZZY; 1.0 for EXACT_ID and STEWARD. |
| `match_evidence` | JSON: normalised strings and rule that matched, so a steward can see *why*. |
| `matching_rules_version` | Which ER rule set produced the row. Lets us run v3 next to v2 and compare. |
| `valid_from`, `valid_to`, `is_current` | SCD2. A merge closes the old row and opens a new one with a different `site_key`. |
| `decided_by` | Who made this link: a steward's user ID, or `system:er-v3` for automatic matches. |
| `decision_reason` | Free text from the steward (NULL for automatic matches). |
| `decision_group_id` | One UUID shared by every row a single steward action opened or closed. A SPLIT undoes a MERGE by finding all rows with the merge's group ID. |

**Key:** `(identifier_type, identifier_value, valid_from)`.
**Rule:** one identifier → exactly one site at any moment (enforced by a constraint).

### fact_inspection — S1, FDA inspection classifications (SCD2)

| Column | Description |
|---|---|
| `inspection_id` | FDA's ID, e.g. `IN-2041187`. Natural key. |
| `valid_from`, `valid_to`, `is_current` | SCD2; `valid_from` = when the weekly snapshot containing this version was loaded. |
| `record_status` | `ACTIVE` or `RETRACTED`. Set to `RETRACTED` when the row disappears from a snapshot. Row kept for audit. |
| `fei_number` | FDA's site identifier → `dim_site_identifier`. |
| `firm_name_as_published` | Verbatim from the CSV. Both Acme spellings are kept. |
| `city` | As published. |
| `country_code` | ISO-2, normalised from `India` / `IN`. |
| `inspection_end_date` | Parsed date. |
| `inspection_end_date_as_published` | Original text, kept because `08/02/2026` is ambiguous and the parser may change. |
| `classification` | `NAI` / `VAI` / `OAI`. |
| `product_type` | As published. |
| `published_date` | As published. |
| `batch_id` | Which weekly file this version came from → `ingest_batch.s3_path`. |

**Key:** `(inspection_id, valid_from)`.

Example, IN-2041187:

| valid_from | valid_to | record_status | classification | batch |
|---|---|---|---|---|
| 2026-10-05 | 2026-10-12 | ACTIVE | VAI | snapshot 10-05 |
| 2026-10-12 | 9999-12-31 | ACTIVE | OAI | snapshot 10-12 |

Example, IN-2040551 (vanished from the 10-12 file):

| valid_from | valid_to | record_status | classification |
|---|---|---|---|
| 2026-10-05 | 2026-10-12 | ACTIVE | OAI |
| 2026-10-12 | 9999-12-31 | RETRACTED | OAI (kept) |

### fact_gmp_document — S2, EU GMP certificates and non-compliance (SCD2)

| Column | Description |
|---|---|
| `doc_ref` | EU's ID, e.g. `EUGMP-NCR-2026-0412`. Natural key. |
| `valid_from`, `valid_to`, `is_current`, `record_status`, `batch_id` | As in fact_inspection. |
| `doc_type` | `GMP_CERTIFICATE` or `NON_COMPLIANCE`. |
| `site_ref` | EU's site identifier → `dim_site_identifier`. |
| `site_name_as_published`, `address_as_published` | Verbatim, UTF-8 (non-ASCII preserved). |
| `country_code` | ISO-2. |
| `issuing_authority` | e.g. `ANSM (FR)`. |
| `inspection_end_date`, `issued_date` | Parsed from DD/MM/YYYY. |
| `status` | `ACTIVE` or `WITHDRAWN` (agency's own status, distinct from our `record_status`). |

Note: duplicates inside one export are removed before loading (same `doc_ref`, same content).

### fact_warning_letter — S3 (SCD2)

| Column | Description |
|---|---|
| `letter_id` | e.g. `WL-320-26-118`. Natural key. |
| `valid_from`, `valid_to`, `is_current`, `record_status`, `batch_id` | As above. |
| `fei_number` | Usually NULL. When NULL the letter is matched by name/address and gets its own `LETTER_ID` row in the bridge. |
| `recipient_firm_as_published`, `recipient_address_as_published` | Verbatim. |
| `country_code` | ISO-2 (derived from the address). |
| `issue_date` | Parsed. |
| `subject` | As published. |
| `body_s3_path` | Letter text stays in S3 (5–60 KB each); only the pointer is here. |
| `source_url` | Agency URL. |
| `nlp_status` | `PENDING` / `DONE` / `FAILED` — progress of the external tagging call. |

### fact_letter_tag — NLP output

| Column | Description |
|---|---|
| `letter_id` | → fact_warning_letter. |
| `tag` | e.g. `DATA_INTEGRITY`. |
| `confidence` | From the NLP service. |
| `nlp_model_version` | Kept so a re-tag adds rows instead of replacing them. |
| `tagged_at` | When. |

**Key:** `(letter_id, nlp_model_version, tag)`.

### fact_enforcement_action — S4 (versioned by the agency)

The agency sends a `version` with every event, so we do not need `valid_to`:
**current state = highest version**. If the highest version is a `RETRACT`, the action is retracted.

| Column | Description |
|---|---|
| `action_id` | e.g. `IA-66-40-0098`. |
| `action_version` | From the event. Key with `action_id`. |
| `event_id` | The stream event that produced this row, for traceability to the S3 event archive. |
| `operation` | `UPSERT` or `RETRACT`. |
| `action_type` | `IMPORT_ALERT` / `RECALL` / `DEBARMENT`. |
| `agency` | e.g. `FDA`. |
| `fei_number` | → `dim_site_identifier`. NULL on a bare RETRACT. |
| `firm_name` | Schema v1 field `firm` and v2 field `firm_name` both land here. |
| `country_code` | ISO-2. |
| `product_codes` | JSON list; v2 only. |
| `effective_date` | Agency's date. |
| `event_time` | Agency's timestamp on the event. |
| `loaded_at` | When we applied it. Used for "what did we show on date X". |

**Key:** `(action_id, action_version)`.

Applying the four sample events in arrival order:

| event | result |
|---|---|
| e-88f1, v1 UPSERT | insert (IA-66-40-0098, 1). Current = v1. Alert. |
| e-91c3, v2 UPSERT | insert (IA-66-40-0098, 2). Current = v2. Alert (changed action). |
| e-88f1 again | rejected: `(IA-66-40-0098, 1)` already exists (primary key). Nothing happens. |
| e-93aa, v3 RETRACT for RC-2026-1187 | insert (RC-2026-1187, 3, RETRACT). We've never seen v1/v2 of it; the row acts as a tombstone so a late v1 cannot become current. No FEI, so no alert; flag for review. |

### dim_watchlist_entry — S5 (SCD2 from CDC)

| Column | Description |
|---|---|
| `watch_id` | From the customer app, e.g. `9912`. Natural key. |
| `customer_id` | → dim_customer. **Row-level security filters on this.** |
| `customer_supplier_ref` | Customer's own supplier code, e.g. `SUP-0071`. |
| `supplier_name_as_typed`, `country_as_typed`, `fei_number_as_typed` | Free text exactly as the customer entered it. |
| `is_active` | `false` after a CDC delete. A delete must stop alerts immediately, so this flag is also pushed to the alert lookup at once. |
| `valid_from`, `valid_to`, `is_current` | SCD2 (customers edit supplier names). |
| `cdc_timestamp` | `ts_ms` from the CDC event; older events are ignored (out-of-order guard). |

Reaches its site through `dim_site_identifier` where `identifier_type = 'WATCH_ID'`.

### fact_alert

| Column | Description |
|---|---|
| `alert_id` | Generated. |
| `customer_id`, `watch_id` | Who is being alerted and why. RLS applies. |
| `site_key` | The site at the time of the alert. |
| `action_id`, `action_version` | Which enforcement action version triggered it. |
| `created_at`, `delivered_at` | Timeline. |

**Unique:** `(watch_id, action_id, action_version)` so the same event can never alert twice.

### match_review_queue — U6 work queue

| Column | Description |
|---|---|
| `identifier_type`, `identifier_value` | The thing we couldn't confidently place. |
| `candidate_sites` | JSON list of `{site_key, score, evidence}`. |
| `status` | `OPEN` / `LINKED` / `NEW_SITE` / `REJECTED`. |
| `opened_at`, `reviewed_by`, `reviewed_at` | Timeline. |

### ingest_batch — lineage

| Column | Description |
|---|---|
| `batch_id` | Generated. Every S1/S2/S3 fact version points at one of these. |
| `source_code` | `S1`, `S2` or `S3`. |
| `received_at` | When the file arrived. Becomes `valid_from` on the fact versions it introduces. |
| `s3_path` | The immutable raw file. This is the "traceable to its source record" link for U1 and the replay input. |
| `row_count`, `status` | `RECEIVED` / `PARSED` / `LOADED` / `FAILED` / `QUARANTINED`. |
| `parser_version` | Which parser produced the load, so a reprocess is distinguishable from the original. |
| `dq_checks` | JSON of the data-quality results for this file (row count vs last week, null rates, date parse failures). |

Stream events (S4, S5) are not tracked here: duplicates are rejected by the fact table's primary key, and replay reads the raw event archive in S3.
